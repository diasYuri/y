# Baseline gaps for later inspection

Activity: `phase-0-baseline-inventory`

These gaps were found while inventorying `pi-mono`. They should be resolved by later baseline behavior, measurement or implementation phases before claiming parity.

## High priority

| Gap | Why it matters | Suggested phase |
|---|---|---|
| Exact CLI compatibility policy for `pi` flags vs target `y` subcommands is undecided | The spec lists `y run`, `y chat`, `y auth`, etc.; legacy code exposes flat flags and package commands | Fase 0 behavior / Fase 4 CLI |
| Full provider behavior matrix is not yet documented | Provider code contains many compatibility branches for OpenAI-compatible, Anthropic, Google, Bedrock and OAuth paths | Fase 0 behavior / Fase 2 providers |
| TUI renderer/input parity is not yet captured as goldens | `packages/tui` has many regression tests and coding-agent-specific components that need exact Go equivalents or accepted deltas | Fase 0 behavior / Fase 5 TUI |
| Session compatibility decision is open | Legacy sessions have v1-v3 migrations, tree entries, labels, compaction and custom extension entries | Fase 0 behavior / Fase 4 sessions |
| TS extension API surface is much larger than WASM V1 target | Current extensions can mutate UI, keybindings, providers, commands, resources and session entries; WASM spec recommends V1 tools/commands only | Fase 8 WASM |
| Package manager resource model needs security review | Current install/update supports npm, git, HTTPS, SSH and local paths; Go migration should not recreate unsafe runtime dependency paths by default | Fase 6 policy / Fase 8 WASM |

## Medium priority

| Gap | Why it matters | Suggested phase |
|---|---|---|
| Auth storage paths differ between `pi-ai` helper and coding-agent auth storage | `pi-ai` writes local `auth.json`; coding-agent uses `~/.pi/agent/auth.json` | Fase 1 config / Fase 2 providers |
| Current settings are JSON, while spec target is TOML | Need import/migration policy and validation errors for old config | Fase 1 config |
| Agent steering/follow-up queues and before/after tool hooks are not yet ported | The new Go agent loop covers the core multi-turn provider/tool cycle, but queue-based steering and hook callbacks from the TS runtime still need a separate migration decision | Fase 4 agent / Fase 5 TUI |
| Image handling needs feature decision | Current code uses Photon WASM/native package and terminal image support; this may bloat minimal Go builds | Fase 1 features / Fase 5 TUI |
| Clipboard support is optional native dependency today | Go equivalent should be optional and isolated | Fase 5 TUI / Fase 6 tools |
| Browser UI strategy is ~~open~~ resolved | Decision: **Option B** (static artifact). `y-web` serves pre-generated assets; Node/Bun only in build pipeline, not runtime. | Fase 7 web |
| `mom` sandbox behavior needs deeper review | Host/docker sandbox and Slack file operations must map to policy capabilities | Fase 7 mom / Fase 3 policy |
| Pods remote setup scripts need inventory | `packages/pods/scripts` are copied into releases and affect y-pods behavior | Fase 7 pods |
| Go `search` tool does not yet implement full `.gitignore` semantics | Legacy `grep` delegates to `rg`, which applies ignore rules; current Go implementation is subprocess-free and only skips `.git` plus explicit globs | Fase 6 search hardening |

## Low priority

| Gap | Why it matters | Suggested phase |
|---|---|---|
| Release/version scripts are not mapped in detail | Current npm release flow will be replaced by Go release artifacts | Fase 9 release |
| Browser smoke behavior is only identified by script name | Needs separate inspection if `y-web` is retained | Fase 7 web / Fase 9 CI |
| Telemetry semantics need explicit decision | Current settings/env include install telemetry override | Fase 1 diagnostics / Fase 9 docs |
| Exact generated model data process is open | `models.generated.ts` is generated by TS; Go needs generated source or embedded data | Fase 2 providers |

## y-pods migration gaps (phase-7-products-pods)

| Gap | Why it matters | Status |
|---|---|---|
| Interactive shell (`y-pods shell`) not yet supported | Legacy spawns `ssh` with inherited stdio; Go binary returns "not yet supported" | Documented gap |
| Log streaming (`y-pods logs <name>`) not yet supported | Legacy tails remote log file via SSH spawn with inherited stdio | Documented gap |
| Agent mode (`y-pods agent <name> [messages...]`) not yet supported | Legacy delegates to pi-agent with base-url/model/api-key inferred from pod config | Documented gap |
| Remote setup scripts not yet ported | Legacy copies `pod_setup.sh` and `model_run.sh` to remote via SCP; Go binary uploads generated scripts but does not bundle the original shell scripts | Documented gap |
| SCP upload not yet tested end-to-end | `FakeSSHClient.SCP` exists but `SetupPod` does not yet copy setup scripts (legacy behavior) | Documented gap |

## y-web migration gaps (phase-7-products-web)

| Gap | Why it matters | Status |
|---|---|---|
| Real browser UI asset generation pipeline not yet wired | The `y-web` server is ready, but the actual build of `pi-mono/packages/web-ui` into `web-assets/` is not yet automated in the Go repo | Documented gap |
| WebSocket / API proxy for SPA not yet implemented | If the SPA needs real-time chat or API calls to the Go backend, a proxy or WebSocket endpoint must be added later | Documented gap |
| Asset embedding (`//go:embed`) not yet used | For single-binary releases, assets could be embedded at compile time; currently only file-system serving is supported | Documented gap |
| HTTPS / TLS auto-configuration not yet implemented | Production deployments will need TLS; current server only supports plain HTTP | Documented gap |

- No functionality was removed in this activity.
- No files under `pi-mono` were modified.
- These gaps are documentation items only; they do not block the baseline inventory acceptance criteria.
