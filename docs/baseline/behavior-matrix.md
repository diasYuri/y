# Functional behavior matrix

Activity: `phase-0-baseline-behavior`

This matrix captures the current `pi-mono` behavior that must be preserved, intentionally changed, or tracked as a migration gap before implementing the Go runtime. Status values:

- `preserve`: keep equivalent user-visible behavior in Go.
- `planned-change`: intentionally change the legacy behavior to match the Go migration spec.
- `gap`: behavior needs a later decision or narrower test before parity can be claimed.

## Core behavior

| Area | Current behavior in `pi-mono` | Status | Source in `pi-mono` | Proposed Go destination |
|---|---|---|---|---|
| CLI bootstrap | `pi` is a flat CLI that starts interactive TUI by default, switches to print mode for `--print` or piped stdin, supports `--mode json`, and starts JSONL RPC for `--mode rpc`. | preserve | `packages/coding-agent/src/cli.ts`, `packages/coding-agent/src/main.ts`, `packages/coding-agent/src/cli/args.ts` | `cmd/y`, `internal/app`, `pkg/coding/headless`, `pkg/coding/rpc` |
| Runtime dependency | Legacy CLI depends on Node/Bun, TypeScript-built packages and optional Bun compiled binary behavior. | planned-change | `packages/coding-agent/src/config.ts`, `packages/coding-agent/src/bun/*` | Remove from main runtime; `cmd/y` must be a Go binary with no Node/Bun runtime dependency. |
| Login and auth selection | TUI `/login` and `/logout` show provider selectors, distinguish API-key versus OAuth providers, show configured/env/runtime status, and open provider OAuth URLs when needed. | preserve | `packages/coding-agent/src/core/slash-commands.ts`, `packages/coding-agent/src/modes/interactive/components/oauth-selector.ts`, `packages/coding-agent/src/modes/interactive/components/login-dialog.ts` | `cmd/y auth login/list/logout`, `internal/auth`, `pkg/tui` auth dialogs |
| Auth storage | Coding-agent credentials live in `auth.json` under the agent dir, are protected with `0600`, use file locking, support API keys, OAuth tokens, runtime overrides and fallback resolvers. | preserve | `packages/coding-agent/src/core/auth-storage.ts`, `packages/coding-agent/src/config.ts` | `internal/auth`, `internal/storage` with atomic writes, locking and permissions |
| Auth environment lookup | Provider auth can come from known env vars, OAuth tokens, Google ADC/project/location, AWS profile/IAM/bearer sources, custom `models.json` keys, or runtime `--api-key`. | preserve | `packages/ai/src/env-api-keys.ts`, `packages/coding-agent/src/core/model-registry.ts`, `packages/coding-agent/src/main.ts` | `internal/auth`, `pkg/providers/auth`, provider-specific config validators |
| `pi-ai` helper auth | Separate `pi-ai login/list` helper exists and writes an auth file relative to current working directory. | planned-change | `packages/ai/src/cli.ts`, `packages/ai/src/oauth.ts`, `docs/baseline/gaps.md` | Fold into `y auth ...`; decide whether a compatibility helper remains only for development. |
| Streaming protocol | Providers emit `start`, text/thinking/tool-call deltas, `done`, and `error` events through `AssistantMessageEventStream`; final message is available via `result()`. | preserve | `packages/ai/src/types.ts`, `packages/ai/src/utils/event-stream.ts`, `packages/ai/src/stream.ts` | `pkg/ai` event types and pull-style `EventStream.Next(ctx)` |
| Agent turn loop | Agent emits `agent_start`, `turn_start/end`, message start/update/end, streams assistant responses, executes tool calls, then continues until no tool calls, steering messages or follow-up messages remain. | preserve | `packages/agent/src/agent-loop.ts`, `packages/agent/src/types.ts` | `pkg/agent` loop and `pkg/coding` session runtime |
| Tool-call execution | Tool calls are schema-validated, prepared, executed sequentially or in parallel, can stream partial updates, and produce `toolResult` messages in assistant source order. | preserve | `packages/agent/src/agent-loop.ts`, `packages/agent/src/types.ts` | `pkg/agent`, `pkg/tools`, bounded worker execution with `context.Context` |
| Tool pre/post hooks | `beforeToolCall` can block execution and `afterToolCall` can override result content/details/error/termination. | preserve | `packages/agent/src/types.ts`, `packages/agent/src/agent-loop.ts` | `internal/policy` preflight plus `pkg/agent` tool lifecycle hooks |
| Approvals and policy | There is no central built-in policy gate. Approvals are mostly extension/UI driven, e.g. extension confirm dialogs and sample destructive-action guards. | planned-change | `packages/coding-agent/src/core/extensions/types.ts`, `packages/coding-agent/src/modes/interactive/interactive-mode.ts`, `packages/coding-agent/examples/extensions/confirm-destructive.ts`, `packages/coding-agent/examples/extensions/permission-gate.ts` | `internal/policy` with allow/deny/require-approval decisions before every sensitive tool |
| Built-in tools | Current built-ins are `read`, `bash`, `edit`, `write`, `grep`, `find`, and `ls`; `read`, `bash`, `edit`, and `write` are the default coding tools. | preserve | `packages/coding-agent/src/core/tools/index.ts`, `packages/coding-agent/src/cli/args.ts` | `pkg/tools` descriptors and handlers; expose spec names such as `read_file`, `run_command`, `search` with legacy aliases if enabled |
| Read tool | Reads text or images, enforces line/byte truncation, supports offset/limit, image resize/attachment notes, and model image capability checks. | preserve | `packages/coding-agent/src/core/tools/read.ts` | `pkg/tools/fs/read_file`; image handling behind optional feature tag |
| Bash tool | Executes through configured shell in cwd, streams stdout/stderr updates, supports optional timeout, aborts process tree, tail-truncates output and writes full large output to temp file. | preserve | `packages/coding-agent/src/core/tools/bash.ts`, `packages/coding-agent/src/utils/shell.ts` | `pkg/tools/shell/run_command` with mandatory timeout/default limits and explicit policy |
| Edit/write tools | `edit` performs exact targeted replacements with diff preview/details and serialized mutation queue; `write` creates parents and overwrites complete files. | preserve | `packages/coding-agent/src/core/tools/edit.ts`, `packages/coding-agent/src/core/tools/write.ts`, `packages/coding-agent/src/core/tools/file-mutation-queue.ts` | `pkg/tools/edit`, `pkg/tools/fs/write_file`, shared mutation queue |
| Search/list tools | `grep` uses `rg`, `find` uses `fd`, both respect ignore semantics and limits; `ls` lists sorted entries including dotfiles with directory suffixes. | preserve | `packages/coding-agent/src/core/tools/grep.ts`, `packages/coding-agent/src/core/tools/find.ts`, `packages/coding-agent/src/core/tools/ls.ts` | `pkg/tools/search`, `pkg/tools/fs/list_files`; prefer Go APIs where practical, subprocesses only with bounded IO |
| Sessions | Sessions are append-only JSONL files with a header, v3 tree entries, message/model/thinking/compaction/branch/custom/label/name entries, and session migrations. | preserve | `packages/coding-agent/src/core/session-manager.ts`, `packages/coding-agent/src/migrations.ts`, `packages/coding-agent/docs/session-format.md` | `internal/storage/session`, `pkg/coding/session`; decide legacy import/read support before cutover |
| Session continue/resume/fork | CLI can continue recent, select resume via TUI, open by path/id, fork existing sessions, and prompt before forking sessions from another project. | preserve | `packages/coding-agent/src/main.ts`, `packages/coding-agent/src/cli/session-picker.ts`, `packages/coding-agent/src/core/agent-session-runtime.ts` | `cmd/y session ...`, `pkg/coding/session`, `pkg/tui` selectors |
| Branch and tree navigation | Runtime can switch, fork, clone, navigate trees, summarize abandoned branches, label entries and export a branch path. | preserve | `packages/coding-agent/src/core/agent-session.ts`, `packages/coding-agent/src/core/agent-session-runtime.ts`, `packages/coding-agent/src/core/session-manager.ts`, `packages/coding-agent/src/modes/interactive/components/tree-selector.ts` | `pkg/coding/session`, `pkg/coding/compaction`, `pkg/tui` tree selector |
| Compaction | Manual and automatic compaction estimate context tokens, reserve recent context, emit compaction lifecycle events and persist summaries. | preserve | `packages/coding-agent/src/core/agent-session.ts`, `packages/coding-agent/src/core/compaction/*`, `packages/coding-agent/src/core/settings-manager.ts` | `pkg/coding/compaction`, `pkg/agent` context transform |
| TUI renderer | Custom TUI performs differential rendering, overlay/focus management, hardware cursor marker handling, terminal image support and input dispatch. | preserve | `packages/tui/src/tui.ts`, `packages/tui/src/terminal.ts`, `packages/tui/src/terminal-image.ts` | `pkg/tui` behind `feature_tui`; renderer buffers must be reused |
| TUI editor/input | Prompt editor, input, kill ring, undo stack, autocomplete, selectors, markdown and message/tool renderers are implemented in TS components. | preserve | `packages/tui/src/editor-component.ts`, `packages/tui/src/components/*`, `packages/coding-agent/src/modes/interactive/components/*` | `pkg/tui/editor`, `pkg/tui/components`, `pkg/coding/ui` |
| Keybindings | Keybindings are named, configurable, include migration from legacy names, and are used by TUI selectors/editor instead of raw key literals in most flows. | preserve | `packages/coding-agent/src/core/keybindings.ts`, `packages/tui/src/keybindings.ts`, `packages/tui/src/keys.ts` | `pkg/tui/key`, `internal/config`; no hardcoded call-site bindings |
| Slash commands | Built-ins include settings, model, scoped-models, export/import/share/copy/name/session/changelog/hotkeys/fork/clone/tree/login/logout/new/compact/resume/reload/quit. | preserve | `packages/coding-agent/src/core/slash-commands.ts`, `packages/coding-agent/src/modes/interactive/interactive-mode.ts` | `pkg/coding/commands`, `cmd/y chat` TUI command router |
| RPC mode | JSONL RPC over stdin/stdout streams session events and accepts prompt, steering, follow-up, abort, session, model, compaction, bash and extension UI commands. | preserve | `packages/coding-agent/src/modes/rpc/rpc-mode.ts`, `packages/coding-agent/src/modes/rpc/rpc-types.ts`, `packages/coding-agent/src/modes/rpc/jsonl.ts` | `pkg/coding/rpc`, `cmd/y run/chat --jsonl` or compatibility mode |
| Print/JSON mode | Print mode sends one or more prompts, writes final assistant text in text mode, or emits header/events as JSON lines in JSON mode, and returns non-zero on assistant error/abort. | preserve | `packages/coding-agent/src/modes/print-mode.ts`, `packages/coding-agent/src/main.ts` | `cmd/y run`, `pkg/coding/headless` |
| Git awareness | Core UI shows current git branch in footer and watches git metadata; git operations are otherwise mostly via bash or extensions. | planned-change | `packages/coding-agent/src/core/footer-data-provider.ts`, `packages/coding-agent/src/modes/interactive/components/footer.ts`, `packages/coding-agent/examples/extensions/dirty-repo-guard.ts`, `packages/coding-agent/examples/extensions/git-checkpoint.ts` | Native `pkg/tools/git` for `git_status`, `git_diff`, `git_commit`; footer uses same bounded git service |
| Git package sources | Package manager supports package resources from npm/git/HTTPS/SSH/local paths and updates installed resources. | gap | `packages/coding-agent/src/core/package-manager.ts`, `packages/coding-agent/src/package-manager-cli.ts`, `docs/baseline/gaps.md` | Replace or constrain through `pkg/extensions/wasm` install/validate flow and `internal/policy` |
